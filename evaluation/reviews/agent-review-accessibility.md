# Agent review: game accessibility (GAG, XAG, WCAG 2.1 AA overlay)

Agent review. Written by a reviewer agent that did not build the course. Not a review by assistive-technology users. Method: code reading, plus headless Playwright on a `VITE_TEST_HOOKS=1` build (keyboard Tab order, dialog state, clicks). No screen reader was run. axe was not re-run; the repo's own axe suite is cited as-is.

## Text-mode parity spot-check (3 objectives end to end)

| Objective | Text path | Result |
|---|---|---|
| 1. Identify and rate | Module 2 → each area section → likelihood/severity radios → Submit → feedback | Works. But every rating form's `<h3>` shows the answer label ("Blocked fire exit", "Guarded side of the machine") above the cue (`hazard-hunt.js:76-77`, called from `app.js:317`). In the assessed and transfer zones that gives the answer away (A1). |
| 3. Analyze causes | Module 3 storyboard → two radio decisions → feedback → causes table | The decisions work. The "Build the contributing-causes chart" heading (`app.js:391`) is followed by a static, pre-filled table of all 5 causes with their levels. Nothing is built, so this is not the same as the 3D causes overlay, and neither is an activity. |
| 5. Report clearly | Module 5 speak-up dialogue → outcome → "Try a different approach" | Works by keyboard. All three outcomes are reachable (also unit-tested). |

Parity verdict: the decision content is shared, so parity holds in the narrow sense. However, the post-check (`items.json` post1–post5) is not rendered in either mode (I searched all 5 module texts; `src` has no reference to `postCheck`). The transfer reflection has a prompt but no input (`app.js:515-516`). Both are gaps in both modes.

## Findings

| # | Severity | Category | Finding | Evidence | Fix |
|---|---|---|---|---|---|
| A1 | critical | Cognitive / assessment integrity | **The rating dialog title is the answer.** In the 3D dialog and the text form alike, `h3 = def.label` ("Missing machine guard", "Clear aisle floor"). The README claims the POI list "doesn't give answers away", but the next screen does. | `hazard-hunt.js:76-77` | In zones with `hints: false`, use `def.area` as the heading. Show `label` only in feedback. |
| A2 | critical | Perception (vision) / motor | **The 3D hunt can't be completed by looking**, because the default viewpoints don't frame most items (visual V1/V2). Keyboard users get 0.2 rad steps and no indication of where to look. The POI list is effectively the only way in, which makes the 3D view decorative for keyboard and low-vision users. | `warehouse.js:476-484` | Re-aim the views. On POI select, also aim the camera at the item (`app.js:199` only jumps to `zone.views[0]`, often the wrong view). |
| A3 | major | WCAG 4.1.2 / 1.3.1 | **The task dialog has `aria-labelledby="task-h"`, but the rating dialog has no `#task-h`** (it renders an `h3` with no id), so the hunt dialog has no accessible name. The replay decision dialog does set `id="task-h"`. | `app.js:36`; `hazard-hunt.js:76` | Give the `h3` `id="task-h"` in `renderRatingDialog` when it is rendered into the dialog. |
| A4 | major | WCAG 2.2.1 Timing | **3D hunt feedback is removed after 14 s** (`setTimeout(() => fb.remove(), 14000)`). It is also not in a live region, so screen-reader users only hear "Rating submitted". The README says "no timers anywhere". | `app.js:169-174` | Keep feedback until dismissed (with a Close button and focus moved to it), and add `role="status"`. |
| A5 | major | Settings honesty (XAG 112/114) | **The FOV, captions-toggle, volume and mute settings do nothing.** `Settings` is built without `onFov`/`onVolume` (`app.js:217`); `captions` is never read by `ShotPlayer`; the course has no audio. Settings that don't work mislead users who rely on them. | `settings.js:58-67`; `app.js:217` | Wire up FOV (`camera.fov`), honor captions-off, and remove the audio controls (or label them "no audio in this course"). |
| A6 | major | Motion (WCAG 2.3.3) | The replay under reduced motion still animates the truck and pedestrian. The orbit "cuts" (fine). S1 reduced-motion auto-advances after 9.8 s with no pause. | `replay-player.js:157-160`; `shot-player.js:71` | Document object motion as essential. Let reduced-motion S1 wait for "Continue". |
| A7 | major | Cognitive / pause | **The replay has no skip or exit control** (only Play/Pause/scrub/orbit), and the replay overlay `.replay-ui` is never removed when the learner leaves Module 3. It stays over Module 2's 3D view, covering the bottom third (`rev-rating-dialog.png`). | `app.js:402-404`; `rev-rating-dialog.png` | Add "Exit replay". Remove or hide `.replay-ui` in `gotoModule`. |
| A8 | major | WCAG 4.1.3 / 1.3.1 | The pre-check uses `role="radiogroup"` containing `<button>`s, not radios (`assess.js:15-16`). Screen readers announce a radio group with no radios, and the feedback isn't announced (only "Correct" or "Answer recorded"). | `assess.js:14-33` | Use a fieldset with buttons (no radiogroup role), and put the feedback in a `role="status"` region. |
| A9 | major | Motor / pointer | **Clicks on items select the wrong object** (exit → "Clear aisle floor"; overhang → "Parked reach truck"; mirror and upright → nothing). Pointer users with low precision are hit hardest. There is no hover or focus highlight on 3D items. | visual V9 | Use hit proxies, a hover outline and a "selected: X, rate it?" confirm step. |
| A10 | minor | WCAG 2.4.3 / clutter | The POI header, an empty list box and the look pad render on non-hunt modules and over text (`rev-menu.png`). The look pad buttons are in the Tab order where they do nothing. | `app.js:102-114`; `focus.js` PoiList | Hide them when `_activeZones()` is empty or text mode is showing. |
| A11 | minor | Cognitive | The POI list needs scrolling inside a 28vh box (`site.css:79`), and only about 5 of 15 items show at a time (`rev-low-dock.png`). Long area names wrap unevenly. | `site.css:79-82` | Group by zone with headings, and allow the panel to expand. |
| A12 | minor | WCAG 1.4.1 | Risk bands use ●/▲/▲▲ plus words (pass). The correct/incorrect choice-button classes rely on color, but the text "Correct." / "Not quite." accompanies them (pass). The replay decision feedback "Consider the alternative:" is softer than it needs to be but is not color-dependent. | `hazard-hunt.js:17-19` | None required. |
| A13 | minor | Keyboard | Arrow-key look works only when focus is not in an input. The Tab order is logical (skip link → header → modules → POI). The text-mode toggle works. Esc closes dialogs (focus trap OK, `focus.js:13-22`). | Tab trace in session | Pass. Consider adding WASD and listing the keys in Settings. |

## Summary
The keyboard structure, dialog focus management and text mode are well built. The blocking problems are assessment-integrity and cue-access issues (A1, A2) plus settings that don't do anything (A5). The README line "Every shot is captioned... Settings: field of view, captions and separate volume controls" overstates what works.
