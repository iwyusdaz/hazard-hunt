# Agent review: independent second pass (all areas)

Agent review, 2026-10-27. Written by a reviewer agent that did not build the course. **Limitation:** the reviewer may run on the same underlying model as the builder (and as the first reviewer), so blind spots may be shared. Nothing here is a review by a real safety trainer, L&D lead, assistive-technology user or learner.

## Why this file exists
While this pass was running, another reviewer committed the seven required reports (`agent-review-{heuristics,cognitive-walkthrough,multimedia-principles,realism-cinematics,accessibility,expert-style,visual}.md`, commit d8a3112). This pass does not overwrite them. It (1) re-checks their key findings independently, and (2) adds defects they did not report. IDs in the form `A1`, `V9`, `H-4` refer to those reports. New findings use `N`.

## Method
- Build: `VITE_TEST_HOOKS=1 npm run build` from the working tree at 21:28 WIB (before the uncommitted `src/scenes/warehouse.js` edits that appeared at 23:43, so the visual results describe the committed scene). Served with `vite preview` on 127.0.0.1:4295.
- Headless Chromium (Playwright 1.64.1) with SwiftShader WebGL at 1440×900, plus a 390×844 mobile emulation. Each preset was set with `__TEST__.engine.quality.set()`. In-frame checks projected each inspectable's world position through each `Warehouse.VIEWS` camera. Clicks were real `page.mouse.click` events.
- Screenshots are listed per finding (files without the `rev-` prefix in `screenshots/` come from this pass). No performance, Lighthouse or headed-GPU testing was done.

| N1 | critical | Interaction / a11y (motor) | **Every mouse click anywhere on the page also fires a 3D raycast.** `pointerdown` is bound to the canvas, but `pointerup` is bound to `window` (`input.js:20-25`), and `_pu` sets `dx = dy = 0` *before* calling listeners, so the "is it a click, not a drag" test in `app.js:92` is always true. `_click` then raycasts through the hidden canvas from the last camera pose. If the ray hits an active-zone item, `_flag` opens (or re-renders) the modal task dialog. ## C. Legal-compliance check (plan §10, re-run)

- Searched `README.md`, `content/`, `src/`, `design/`, `public/showcase.json` and `index.html` for compliance, certification and accreditation wording. **No claim of regulatory compliance or certification was found.** The only hits are "slide-based compliance training" (README:15, describing the problem), "Compliance-only reporting" (`items.json:4`, a distractor's feedback) and the disclaimer itself.
- The required sentence, "This course does not replace training required by law or by your employer.", is present in **Module 1** (`app.js:255`), README:11, `showcase.json` summary and `design/manager-guide.md:5`. `index.html:6` paraphrases it ("Does not replace legally required training").
- **Gap (minor, N17):** in the app, the disclaimer appears only once, as the last sentence of Module 1's second paragraph. A learner who jumps straight to a module through the tabs, or who finishes in Module 5, never sees it again, and there is no completion screen to repeat it. **Fix:** show it in the footer or the Menu dialog, and on the completion summary that H-4/L1 call for.
- The OSHA references are US-specific background, and the course never states a jurisdiction (agree with L8/S4). This doesn't imply compliance, but should be labeled "US OSHA (background only)".
